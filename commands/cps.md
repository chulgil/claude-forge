# CPS Command — Context · Problem · Solution

고객의 발산적 요구사항을 **구조화된 CPS 문서**로 수렴한다.

> 하네스 엔지니어링(스페이스YY)의 CPS 프레임을 Claude Forge에 통합.
> `/plan` 앞 단계에서 사용. "무엇을 만들 것인가?"를 정의한다.

## 언제 사용하는가

- 고객/이해관계자 미팅 후 요구사항 정리
- 새 기능의 "왜?"를 명확히 하고 싶을 때
- 여러 요구사항이 뒤섞여 문제 정의가 불분명할 때
- `/plan` 실행 전 방향 설정

## 워크플로우 위치

```
미팅/요구사항 → /cps (문제 정의) → /plan --ceo (방향) → /plan --eng (구현) → /tdd
```

---

## Task

### 0단계: 입력 수집

`$ARGUMENTS`에서 요구사항 텍스트를 받는다.

입력이 없으면 대화형으로 질문:
```
CPS 문서를 작성합니다. 다음 중 하나를 입력해주세요:

1. 고객/이해관계자의 요구사항 (자유 형식)
2. 미팅 로그 또는 노트
3. 해결하고 싶은 문제 설명

자유롭게 입력하세요. 제한하지 않습니다.
```

---

### 1단계: 발산 — 요구사항 분석

입력된 내용을 분석하여 다음을 추출한다:

**1-1. 이해관계자 식별**
```
누가 관련되어 있는가?
- 직접 사용자: [예: 선생님, 학생, 학부모]
- 간접 이해관계자: [예: 관리자, 운영팀]
- 시스템: [예: 결제 시스템, 알림 서비스]
```

**1-2. 요구사항 분류**

| 분류 | 요구사항 | 우선순위 |
|------|---------|---------|
| 핵심 (Must) | | |
| 희망 (Should) | | |
| 있으면 좋은 (Could) | | |
| 제외 (Won't) | | |

**1-3. 소프트웨어 구성 요소 도출**

요구사항에서 필요한 소프트웨어 단위를 식별:
```
예: 배달 플랫폼 → 고객앱 + 기사앱 + 업주앱 + 어드민
예: 레슨앱 → 선생님앱 + 학생앱 + 학부모뷰 + 관리자
```

---

### 2단계: 수렴 — CPS 문서 작성

분석 결과를 CPS 프레임으로 구조화한다:

```markdown
# CPS: [프로젝트/기능명]

> 작성일: [날짜]
> 버전: 1.0
> 상태: 초안 | 검토중 | 확정

---

## Context (맥락)

우리가 공유하고 있는 배경 지식:

- **도메인**: [업계/분야 설명]
- **현재 상태**: [기존 시스템, 프로세스, 제약사항]
- **이해관계자**: [관련자와 그들의 역할]
- **전제 조건**: [깔고 가는 가정들]

---

## Problem (문제)

해결해야 할 구체적 문제:

### 핵심 문제
[1~2문장으로 핵심 문제 정의]

### 세부 문제
1. [문제 1] — 영향: [누구에게, 어떻게]
2. [문제 2] — 영향: [누구에게, 어떻게]
3. ...

### 현재 해결 방법과 한계
- [기존 방법]: [왜 부족한지]

---

## Solution (솔루션)

제안하는 해결 방향:

### 솔루션 개요
[1~3문장 요약]

### 구성 요소

| 컴포넌트 | 역할 | 대상 사용자 |
|---------|------|-----------|
| | | |

### 핵심 플로우
[ASCII 다이어그램으로 주요 흐름 표현]

### 기술적 제약/결정
- [제약 1]: [이유]
- [결정 1]: [근거]

### 범위 밖 (명시적 제외)
- [제외 항목 1]: [이유]

---

## 다음 단계

- [ ] CPS 리뷰 완료
- [ ] `/plan --ceo` 실행 (제품 방향)
- [ ] `/plan --eng` 실행 (구현 계획)
```

---

### 3단계: 저장 & 안내

**3-1. 파일 저장:**

프로젝트 루트에서 문서 위치를 결정:
- `docs/` 폴더 있으면 → `docs/cps-[기능명].md`
- 없으면 → `cps-[기능명].md`

기존 CPS 문서가 있으면 버전을 올린다 (1.0 → 1.1).

**3-2. 완료 안내:**

```
CPS 문서가 저장되었습니다: [경로]

다음 단계:
  /plan --ceo [기능명]    제품 방향 검토
  /plan --eng [기능명]    구현 계획 수립
```

---

## 사용 예시

```bash
# 자유 형식 입력
/cps 학부모가 자녀의 연습 현황을 실시간으로 보고 싶어해요. 주간 요약도 필요하고, 레슨 피드백도 확인하고 싶어합니다.

# 미팅 로그 입력
/cps 오늘 미팅에서 나온 내용: 결제 시스템 도입 필요, 구독제 vs 건별 결제 논의, 환불 정책 미정, PG사 선정 필요

# 간단한 문제 정의
/cps 알림이 너무 많아서 사용자가 중요한 알림을 놓치는 문제
```

## 관련 커맨드

| 순서 | 커맨드 | 역할 |
|------|--------|------|
| **1 (현재)** | `/cps` | 문제 정의 |
| 2 | `/plan --ceo` | 제품 방향 |
| 3 | `/plan --eng` | 구현 계획 |
| 4 | `/tdd` | 테스트 주도 구현 |
